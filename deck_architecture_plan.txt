PLAN D'ARCHITECTURE DU SYSTÈME DE DECKS (MODE HISTOIRE & IA)

1. DECKS JOUEUR (MODE HISTOIRE)
-------------------------------
Objectif : Decks préconstruits imposés au joueur durant certaines scènes du scénario.
Structure :
- Scripts par Chapitre : Créer un script distinct pour chaque chapitre pour éviter un fichier monolithique.
  - Exemple : `scripts/sStoryDecks_Chap1/sStoryDecks_Chap1.gml`
  - Exemple : `scripts/sStoryDecks_Chap2/sStoryDecks_Chap2.gml`
- Manager Central : Un script `sStoryDeckManager.gml` pour récupérer les decks en fonction du chapitre demandé.
- Intégration Éditeur : 
  - Dans `oScenarionCreatorUI`, le bouton de sélection de deck filtrera les decks affichés en fonction du chapitre actuellement édité (via `global.current_chapter`).
  - L'ID du deck choisi sera sauvegardé dans le fichier JSON du scénario.

2. DECKS BOT (MODE HISTOIRE & CONTRE IA)
----------------------------------------
Objectif : Decks utilisés par l'IA, servant à la fois pour les duels scénarisés (Histoire) et les parties libres (Contre IA).
Structure :
- Scripts par Chapitre : Comme demandé, organisation par chapitre pour suivre l'évolution de l'histoire.
  - Exemple : `scripts/sBotDecks_Chap1/sBotDecks_Chap1.gml` (Contient les decks des ennemis rencontrés au Chapitre 1).
- Utilisation Mixte :
  - Mode Histoire : Le scénario impose un ID de deck bot spécifique (ex: "B_CH1_BOSS").
  - Mode Contre IA : Le menu de sélection listera tous ces decks (ou les débloquera au fur et à mesure), permettant au joueur de choisir son adversaire.

3. CONVENTIONS DE NOMMAGE (IDs)
-------------------------------
- Joueur : `P_CH[X]_[NOM]` (ex: `P_CH1_TUTO`)
- Bot : `B_CH[X]_[NOM]` (ex: `B_CH1_GARDIEN`)

Ce fichier sert de référence pour l'implémentation future.
