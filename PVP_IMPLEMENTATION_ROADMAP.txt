ROADMAP TECHNIQUE : IMPLEMENTATION MODE PVP (JOUEUR CONTRE JOUEUR)
===================================================================

Cette roadmap détaille les étapes techniques nécessaires pour transformer l'architecture "Solo" (Hero vs IA) en architecture "Multijoueur" (Client-Serveur / Peer-to-Peer via Hôte).

PHASE 1 : LA STANDARDISATION (ARCHITECTURE "COMMAND PATTERN")
-------------------------------------------------------------
Objectif : Séparer l'interface (Clics) de la logique (Règles). Le jeu ne doit plus dépendre de "qui clique" mais de "quelle commande est reçue".

[ ] 1.1. Création du Contrôleur d'Actions (sGameActionController)
    - Créer un script central `ExecuteGameAction(action_type, payload)` qui reçoit une structure de données.
    - Définir les constantes d'Actions : `ACTION_END_TURN`, `ACTION_SUMMON`, `ACTION_ATTACK`, etc.
    - Ce script deviendra le SEUL point d'entrée pour modifier l'état du jeu.

[ ] 1.2. Migration de la Fin de Tour
    - Modifier `oNextStep` (bouton Fin de Tour).
    - Remplacer la modification directe de `game.nbTurn` par `RequestAction("END_TURN")`.

[ ] 1.3. Migration des Invocations (Summon)
    - Modifier `oCardParent` / `oHand` (Drag & Drop).
    - Remplacer la création d'instance directe par `RequestAction("SUMMON", { card_id, slot_index })`.
    - Le contrôleur vérifiera le mana et placera la carte.

[ ] 1.4. Migration des Attaques
    - Modifier le système de ciblage.
    - Implémenter des UID (Unique IDs) temporaires pour les cartes sur le terrain afin de les identifier sur le réseau.
    - Envoyer `RequestAction("ATTACK", { attacker_uid, target_uid })`.

PHASE 2 : L'INFRASTRUCTURE RESEAU (LE "TUYAU")
-----------------------------------------------
Objectif : Connecter deux machines et échanger des données brutes.

[ ] 2.1. Création du oNetworkManager
    - Gestion des Sockets TCP (GameMaker Network).
    - Fonctions `HostGame(port)` et `JoinGame(ip, port)`.

[ ] 2.2. Protocole de Communication
    - Structure des paquets : `[HEADER] + [PAYLOAD JSON]`.
    - Messages : `MSG_HELLO`, `MSG_GAME_START`, `MSG_GAME_ACTION`, `MSG_SYNC`.

[ ] 2.3. Synchronisation et RNG
    - Implémenter le "Handshake" (Vérification de version).
    - Synchronisation de la Seed RNG : L'Hôte envoie une graine aléatoire au début.
    - `random_set_seed(shared_seed)` pour garantir les mêmes pioches.

PHASE 3 : L'INTEGRATION PVP (LE "CERVEAU")
------------------------------------------
Objectif : Faire comprendre au jeu qu'il y a un "Autre Joueur" humain.

[ ] 3.1. Gestion de l'Identité (Local vs Remote)
    - Modifier `oGame` pour gérer les états `PLAYER_LOCAL` et `PLAYER_REMOTE`.
    - Bloquer les inputs souris quand c'est le tour du `PLAYER_REMOTE`.

[ ] 3.2. Réception des Commandes
    - `oNetworkManager` reçoit `MSG_GAME_ACTION`.
    - Décodage du JSON -> Envoi à `sGameActionController`.
    - Le jeu exécute l'action à distance (comme si l'IA jouait).

[ ] 3.3. Masquage d'Information
    - S'assurer que les données de la main adverse ne sont pas envoyées/affichées.
    - Gestion du brouillard de guerre (cartes face cachée).

PHASE 4 : INTERFACE ET UX
-------------------------
Objectif : Rendre le mode accessible et jouable.

[ ] 4.1. Menu Multijoueur
    - Nouvelle Room `rLobby`.
    - Boutons "Créer Partie" / "Rejoindre" (Champ IP).

[ ] 4.2. Feedback Visuel
    - Indicateur "Tour de l'adversaire...".
    - (Optionnel) Visualisation des cibles adverses (flèches fantômes).

[ ] 4.3. Gestion des Erreurs
    - Écran de victoire par forfait si déconnexion.
